# 家人生日提醒

点击日历顶部的 🎂「家人生日」，填写家人称呼，选择公历或农历的月份、日期；农历可勾选闰月。不要求填写出生年份，也不计算年龄。

生日显示在月历和近期倒计时中。按设备本地时间，在生日前一天 20:00 和生日当天 09:00 提醒。应用在当天上午 09:00–12:00 打开时可以补发；晚间在 20:00–24:00 打开时可以补发。不会在第二天补发前晚通知。

网页需要保持打开，系统通知需要浏览器授权；没有授权时使用页内提示。客户端需要保持运行，隐藏到托盘后仍会检查。完全退出应用后不会发送提醒。通知不调用 AI。

## 每年如何计算

- 公历生日：按月日重复，2 月 29 日在平年按 2 月 28 日。
- 普通农历生日：按农历年换算，普通月和闰月分别处理，同年不会重复过两次。
- 闰月生日：有对应闰月时使用闰月，没有时使用普通月份。
- 农历三十遇到只有 29 天的小月：按廿九。

农历换算复用项目已有的 lunar-javascript，见[官方说明](https://6tail.cn/calendar/start.html)。年初会从当前农历年开始寻找生日，避免遗漏公历年初对应的上一农历年腊月生日。

## 保存与同步

生日以原有 `anniversaries` 实体上的可选 `birthday` 字段保存，继续使用现有账号隔离、更新时间合并和删除墓碑，不新增数据库表。原有纪念日保持原来的行为。生日实体的 `date` 保留兼容占位值，真正日期由 `birthday` 规则计算；不能用该占位值直接显示生日。

网页、Electron 主进程、Node API 和 Java Cloud API 均保留及校验新字段。新版服务端合并旧客户端上传时会保留已知的生日规则，仍允许名称更新和删除。提醒前主动同步最新数据；有效提醒时段内最多每五分钟发起一次刷新，离线时使用本地数据。成功发送后按账号、生日日期和早晚阶段去重，设备之间各自通知。

服务端通过 `/api/health` 声明 `birthday-reminders-v1`。本地有生日而服务器尚不支持时，新版同步引擎会保留本机数据并提示升级，防止旧服务器清洗新字段。

上线需要同时更新网页、客户端，以及 Node 后端、Java calendar-service 和 gateway；共享模式必须让两个后端都支持生日字段后再开始使用，以避免另一后端清洗共享数据库中的新字段。本次本地构建并不表示服务器或已安装客户端已经更新。

## 验证

生日测试覆盖农历换算、跨年、闰月、小月、两次提醒时间点、删除、持久化去重、通知失败重试、账号切换和旧服务端保护。59 组 TypeScript/Java/Node 兼容用例包含生日字段清洗和旧客户端合并。客户端冒烟测试使用临时数据目录，验证生日新增、完整快照替换后重载、删除和 IPC 桥接，不修改用户数据。
